# hero/controllers/

Hero's half of the Controller layer (see `src/README.md`'s "Generic vs.
Hero-specific split"): axum routers for this template's worked CRUD
example, plus the concrete `AppState` every router (Hero's own and
`generic::controllers`' generic ones) is instantiated with. Highest layer
besides `main` itself — may import from every layer below it, nothing
may import from here.

- `mod.rs` — `AppState` (shared, cloned per-request state: `Settings`,
  `OidcVerifier`, `HealthRegistry`, Hero's `CrudService`,
  `rate_limit::RateLimiter`, `EventBus`), the Hero role-set constants
  (`HERO_READ_ROLES`/`HERO_WRITE_ROLES`/`HERO_DELETE_ROLES`, `FR-0015`),
  `HERO_EVENT_RESOURCE`, the `DynHeroRepository` type generated by
  `generic::repositories::dyn_repository!`, and `AppState`'s impls of
  `oidc::HasOidcVerifier` and `generic::controllers`'s `HasSettings`/
  `HasHealthRegistry`/`HasRateLimiter` — what let `generic::controllers`'
  own routers mount onto this concrete state with zero dependency on it.
  See its own module doc for why `AppState` (rather than something
  purely generic) is where this app's one resource-specific dependency
  lives.
- `heroes.rs` — the Hero v2 resource router (list/get/create/update/
  delete), mounted by `lib.rs` at `/crud/v1/heroes/v2/json`. Owner-
  scoped (`docs/adrs/0007`), soft-deleted (`docs/adrs/0008`), RBAC-gated
  per the role constants above. create/update/delete are rate-limited
  (`FR-0023`, `docs/adrs/0011`) via `AppState::rate_limiter`, keyed by
  the caller's `ConnectInfo<SocketAddr>`. list supports filtering/
  sorting, and update/delete support a bulk form over filters
  (`FR-0025`/`FR-0026`, `docs/adrs/0013`) via `generic::controllers::
  crud_query`/`crud_actions`. Also mounts `/stats`/`/predict`
  (`FR-0028`/`FR-0029`, `docs/adrs/0015`) via `generic::controllers::
  crud_stats`, and `/events` (`FR-0030`, `docs/adrs/0016`) via
  `generic::controllers::crud_events`. Every mutating handler announces
  what it did on that stream after the write succeeds.
- `heroes_xml.rs` — the XML sibling of `heroes.rs`, mounted by `lib.rs`
  at `/crud/v1/heroes/v2/xml` (`FR-0027`, `docs/adrs/0014`). Shares
  `heroes.rs`'s `HERO_FIELD_SPECS`/`HERO_WRITE_RATE_SCOPE` and calls the
  exact same `generic::controllers::crud_actions` functions — only the
  request/response (de)serialization (`quick_xml` instead of `Json`)
  differs.
- `heroes_v1.rs` / `heroes_v1_xml.rs` — the deprecated, `superpower:
  String`-shaped v1 compat siblings (`docs/adrs/0017`, `FR-0031`/
  `FR-0032`) at `/crud/v1/heroes/v1/{json,xml}` — lossy DTO conversion
  in `hero::views::hero_v1`/`hero_v1_xml`, no separate storage. Every
  route attaches RFC 8594 `Sunset`/`Deprecation`/`Link` headers via
  `http_headers::Sunset` (NFR-0026).
- `heroes_web.rs` (+ `heroes_web_components.js`) — a third
  representation of the same resource at `/heroes/form` /
  `/heroes/components.js`: a progressively-enhanced HTML form, working
  with no JavaScript, calling the same `generic::controllers::
  crud_actions` path as every other sibling (`FR-0034`).

A resource's own router lives here as a small file per resource (e.g.
`heroes.rs`); the generic CRUD machinery it's built from lives in
`crud/`/`generic::repositories`/`generic::controllers`, not here — this
package is the one place allowed to reference both `generic::*` and
Hero's own concrete types together. Adding another resource follows the
same shape: its own sibling package (`crate::<resource>::controllers`,
mirroring this one), never a file added here.

## Do

- Give a new Hero route its own handler here, built from
  `generic::controllers::crud_actions`'s shared resolve functions plus
  this package's own `AppState`/role constants.

## Don't

- Add resource-agnostic logic here that a second resource could reuse
  unchanged — that belongs in `generic::controllers` instead.
